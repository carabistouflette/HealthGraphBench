# Contrôles temporels accessibles — lot B

Lecture ciblée du code et des limites RC1 le 2 octobre 2026. Ce contrôle statique décrit ce que font les chemins conservés ; il ne réingère pas les sources, ne réentraîne pas les modèles et ne certifie pas la disponibilité publique historique des champs.

| Tâche | Contrôle accessible | Source | Limite persistante |
|---|---|---|---|
| MAUDE | Positifs admissibles calculés avant l'ajout du trimestre ; fits avant 2023Q1/2024Q1/2025Q1 ; lignes tabulaires accumulées avant la cible ; histoire mise à jour après son évaluation. Le contrôle de faisabilité retrouve le graphe 2023 et les 3 483 observations positives. | `healthgraphbench/tasks/maude/evaluate.py::run_gate`, `eligible_edges` ; `models.py::History`, `candidate_problems` ; [faisabilité MAUDE](maude_diagnostic_feasibility.md). | `DATE_RECEIVED` n'est pas une date prouvée de publication du champ. Les fits historiques ne sont pas réexécutés et les champs tabulaires complets ne sont pas dans les snapshots préparés. |
| CMS | Pour une année y, `CmsNursingTask._run_all` prend les lignes 2019 à y−1 ; `fit_logistic_gate` calcule moyennes/écarts-types sur ces seules lignes. `history_stats` utilise `bisect_left`, donc exclut l'inspection cible et conserve la frontière des fenêtres 365/730 jours. | `healthgraphbench/tasks/cms_nursing/task.py::_run_all`, `models.py::fit_logistic_gate`, `prepare.py::history_stats`. | Les associations de propriétaire sont filtrées par date ≤ cible, non strictement avant ; dates de fin et publication incomplètes. Le filtre n'établit ni propriété active juridiquement complète ni connaissance publique de l'association. |

L'interface courante consomme l'artefact historique, pas un entraînement nouveau. |

Le départage MAUDE et Part D conserve le soutien global historique avant le code canonique. Une convention générique « score puis code » ne suffit pas à décrire ces deux chemins.

La présence des fichiers ne certifie pas chaque décision de développement. Le manuscrit RC1 (`sections/body_fr.tex`) déclare les périodes consultées, l'horloge MAUDE, la sélection/troncature CMS et la distinction service/publication Part D. Aucune origine véritablement non consultée n'est attestée par les pièces livrées ; la branche de confirmation n'est donc pas engagée et n'est pas remplacée par ces contrôles.

Lors du contrôle final A/B, avant instrumentation C, les définitions GraphSAGE vendoriées ont été comparées au noyau source épinglé ; cette égalité n'était pas une preuve d'apprentissage sur MAUDE. Le [diagnostic C exécuté](maude_duration_diagnostic.md) apporte ses propres observations, sans prouver la disponibilité publique historique. Les tests de frontières temporelles du dépôt et les traces d'exécution ne remplacent pas la responsabilité du second lecteur humain.
